三、其他
main.cpp 的 setApplicationName("Termail_v6.2") 与 config.h 的 APP_NAME = "Termail_final" 不一致

proot_commands.cpp 的 pre-position 里字符串字面量嵌套笔误（QString output = R"( ... QString output = R"(），会导致原始字符串提前结束，编译可能报错或输出异常

snake.cpp 的 tick() 里“撞墙判断”重复出现两次（函数开头一次，末尾又有一段 if (newHead.x() < 0 ...)），逻辑冗余但不会崩溃

enhanced_commands.cpp 的 countdown 用 \r 刷新在 QTextEdit 里不会真的覆盖上一行，会逐行堆叠

enhanced_commands.cpp 的 parallel 用 QProcess* 异步启动，但 ui->appendOutput 在 lambda 里被多线程调用，QTextEdit 非线程安全，存在并发写 UI 的隐患

config_commands.cpp 的 backup/restore 只处理 custom_commands.json、aliases.json、.ssh，未处理字体设置（QSettings）与 .termail_cmd.log

many4.cpp 里 copy 命令覆盖了 file_commands.cpp 的 copy（registerCommand 有防重复注册，先注册的 file_commands.cpp 生效，所以 many4 的 copy 实际被丢弃）

many4.cpp 的 session-* 命令直接访问 ui->sessions[id]，id 不存在时未判断（session-rename 有判，session-info/session-export 有判，session-rename 也判了）

notify_commands.cpp 依赖 com.termail.terminal.TermailService 这个 Java 类，但工程里未提供对应 .java 源码，需在 android/ 目录下自行提供

utils.cpp 的 g_processCount 在 timeout 触发 kill 时未 fetchAndSubOrdered，进程计数可能泄漏（finished 信号会触发减 1，但如果 kill 后 finished 不派发则漏减）

terminal.cpp 的 vibrate 里 vibrator.callMethod<jboolean>("vibrate", "(J)Z", ...) 签名不对，Vibrator.vibrate(long) 返回 void，应为 "vibrate", "(J)V"；且 Android 8+ 需要 VibrationEffect

system_commands.cpp 的 brightness 里 attrs.setField<jdouble>("screenBrightness", brightness) 字段类型应为 float，LayoutParams.screenBrightness 是 float，JNI 传 jdouble 会类型不匹配
